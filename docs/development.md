# Разработка MyRSUH

Команды выполняются из корня проекта в PowerShell, если не указан другой каталог.

## Установка и локальный запуск

Нужны Python 3.12 или новее, Node.js 22.12 или новее и pnpm.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.lock.txt
pnpm --dir frontend install --frozen-lockfile
.\start.ps1
```

Приложение откроется по адресу `http://127.0.0.1:5173/`. Окно PowerShell должно оставаться открытым до окончания работы. Ctrl+C останавливает оба сервера.

Для проверки с телефона подключите устройства к одной Wi-Fi сети и запустите `start.ps1 -Lan`. Скрипт выведет адрес для телефона. Настройки каждого браузера сохраняются отдельно.

`start.ps1` совместим с Windows PowerShell 5.1 и PowerShell 7. При редактировании сохраняйте UTF-8 с BOM. Логи запуска находятся в `.logs`.

## Ручной запуск

В первом окне PowerShell запустите backend.

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором окне запустите frontend из корня проекта.

```powershell
pnpm --dir frontend dev
```

Документация локального API доступна по адресу `http://127.0.0.1:8000/docs`. Vite направляет `/api` в backend.

## Проверки

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest -q
cd ..\frontend
pnpm test
pnpm run build
```

`start.ps1 -NoBrowser -SmokeTest` проверяет запуск серверов и останавливает их после проверки. Результаты предыдущих проверок описаны в [TEST-REPORT.md](../TEST-REPORT.md).

## Состав проекта

- `backend/app/config` содержит каталог групп и расписание звонков.
- `backend/app/services` отвечает за запросы к РГГУ, нормализацию и серверный кеш.
- `frontend/src/pages` содержит основные экраны.
- `frontend/src/features` содержит первый вход и поиск предметов вместе с их тестами.
- `frontend/src/components` содержит общие элементы интерфейса.
- `frontend/src/services` отвечает за HTTP-запросы и офлайн-копии расписаний.
- `frontend/src/lib` содержит общие вычисления и работу с локальными настройками.

## Конфигурация и данные

Параметры backend описаны в `backend/.env.example` и `backend/app/settings.py`. Файл `backend/.env` исключён из Git.

Обновление каталога выполняется командой `.\.venv\Scripts\python.exe backend/import_groups.py`. После изменения каталога перезапустите backend. Импорт включает ИИНиТБ и дополнительную группу Института психологии `213_1` для формы `3` и курса `2`.

Основной знак находится в `frontend/public/icon-512.png`. Скрипт `scripts/create-icons.ps1` создаёт остальные размеры. Логотипы тем находятся в `frontend/public/images`.

## Статическая сборка и публикация

Workflow `.github/workflows/pages.yml` выполняет проверки, экспорт данных, сборку и публикацию GitHub Pages. Плановый запуск назначен на 23:00 по Москве. Также доступны ручной запуск через Actions и запуск после отправки изменений в `main`.

Экспорт `backend/export_static.py` использует общий клиент РГГУ и нормализацию. При временном сбое он может использовать опубликованную копию возрастом до семи дней. При отсутствии пригодных данных публикация прерывается, сохраняя предыдущую версию сайта.

Для проверки статической сборки используйте отдельное окно PowerShell.

```powershell
.\.venv\Scripts\python.exe backend/export_static.py
$env:VITE_DATA_SOURCE = 'static'
$env:VITE_BASE_PATH = '/myrsuh-client/'
pnpm --dir frontend run build
pnpm --dir frontend exec vite preview --host 127.0.0.1
```

Адрес проверки — `http://127.0.0.1:4173/myrsuh-client/`. После проверки закройте это окно PowerShell, чтобы параметры статической сборки не влияли на обычный локальный запуск.

Запуски GitHub Actions по расписанию могут задерживаться. После 60 дней отсутствия активности в публичном репозитории GitHub может отключить их. Проверка состояния и повторное включение доступны во вкладке Actions.

## Офлайн-режим

Сервис-воркер сохраняет интерфейс, иконки и шрифты. Расписания сохраняются только для добавленных групп и удаляются из кеша при удалении группы. Поиск новых групп требует подключения.

Для проверки откройте production-сборку, дождитесь загрузки расписания, остановите сервер и перезагрузите вкладку. На iPhone используйте HTTPS и добавление на домашний экран через Safari.

В публичном репозитории эта документация, исходный код и история коммитов доступны всем. Пароли, токены и личные настройки должны храниться вне Git.
