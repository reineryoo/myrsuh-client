# MyRSUH

Локальное приложение расписания РГГУ: FastAPI / Python 3.12+ и React / TypeScript / Vite. Данные поступают с реального API университета. Демонстрационных занятий в приложении нет.

## Быстрый запуск на Windows

Нужны Python 3.12 или новее, Node.js 22.12+ и pnpm. После установки зависимостей:

```powershell
.\start.ps1
```

Откроется http://127.0.0.1:5173/. Скрипт запускает оба сервера в фоне и останавливает их при Ctrl+C. Оставьте окно PowerShell открытым. Если политика компьютера запрещает скрипты, используйте ручной запуск ниже — менять системную политику не требуется.

Скрипт совместим с Windows PowerShell 5.1 и PowerShell 7. При редактировании `start.ps1` сохраняйте кодировку **UTF-8 с BOM**, чтобы PowerShell 5.1 правильно читал русские сообщения. Если Node.js не добавлен в PATH, скрипт также проверяет установленный локальный runtime Codex.

В этом рабочем каталоге зависимости уже установлены. Для нового компьютера выполните из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.lock.txt
cd frontend
pnpm install --frozen-lockfile
cd ..
```

Если установлена другая подходящая версия Python, замените `py -3.12` на путь к её интерпретатору. Активация окружения не обязательна.

## Ручной запуск

Первое окно PowerShell, из корня проекта:

```powershell
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Второе окно:

```powershell
cd frontend
pnpm dev
```

Интерфейс: http://127.0.0.1:5173/. Документация API: http://127.0.0.1:8000/docs. Vite направляет запросы `/api` в FastAPI. По умолчанию оба процесса доступны только на компьютере; публичная публикация не выполняется.

## Проверка с телефона по Wi-Fi

Подключите компьютер и телефон к одной обычной Wi-Fi сети. Остановите предыдущий запуск через Ctrl+C и выполните:

```powershell
.\start.ps1 -Lan
```

Скрипт выберет локальный адрес Wi-Fi (либо Ethernet) и напечатает строку **«С телефона в той же Wi-Fi сети»** с готовой ссылкой. Откройте именно эту ссылку в браузере телефона. Адрес 127.0.0.1 на телефоне означает сам телефон, а не компьютер.

Пока проверяете, компьютер должен оставаться включённым, а окно запуска — открытым. Настройки группы и темы на телефоне сохраняются отдельно от компьютера. Режим `-Lan` открывает frontend на выбранном частном сетевом адресе; backend остаётся на 127.0.0.1, и телефон обращается к нему через frontend. Пароли или публичный доступ в интернет для этого не нужны.

Если Windows спросит о сетевом доступе для Node.js, разрешите его для вашей доверенной частной сети. Скрипт не меняет правила брандмауэра. Если страница не открывается, проверьте одинаковую сеть, отсутствие гостевой изоляции Wi-Fi и не перенаправляет ли VPN локальные адреса.

## Что реализовано

- В настройках доступны четыре мягких акцента: голубой, зелёный, красный, фиолетовый. Выбор сохраняется, как и тема. Имя «Студент» использует этот акцент; цвета типов занятий остаются неизменными.
- Переключатель «Прошедшие пары вниз» по умолчанию включает активные пары сверху и серые прошедшие ниже. При отключении сохраняются обычный порядок и цвета. Ни одно занятие не скрывается. Настройка общая для главной, списка дня и результатов поиска предметов.
- В шапке календаря показана выбранная неделя из числа недель загруженного семестра. Например, для 03.11.2026 и периода 24.08.2026–21.03.2027 это 11-я неделя из 30. Недели начинаются с понедельника; количество берётся из периода РГГУ, а не из дат первого/последнего занятия. В кнопке группы две последние части шифра через пробел, например «ПИ ПИИ». Стрелки над полоской дней листают недели и сохраняют выбранный день недели.

- **Главная:** приветствие студенту по московскому времени, реальные сегодняшние пары, отсчёт до первой/следующей, текущая пара и прогресс. Для завершённого и свободного дня — панель с планом на завтра. Историй и фиктивных дедлайнов нет.
- Календарь включает день, неделю ПН–ВС, месяц и обзор семестра. Динамическая красная линия проходит по карточкам и перерывам. Текущая пара слегка увеличивается и подсвечивается. Поиск предлагает предметы без повторов. После выбора показаны все записи предмета, завершённые пары и остаток по типам. Подсчёт относится к загруженному периоду и объединяет одновременные записи подгрупп. Прошедшие карточки серые в главной, списке дня и поиске. Недельная и месячная сетки сохраняют цвета.
- **Настройки:** отдельная страница с темой, звонками, временем получения данных, инструкцией для iPhone и сбросом. Ровно три кнопки нижнего меню.
- **Группы:** поиск групп ИИНиТБ по шифру, направлению и профилю. Результаты появляются после ввода на первом входе и в разделе «Добавить расписание». Сохранённые группы можно переключать и убирать через экран «Расписания».
- **Цвета:** лекции мятные, практика/семинары голубые, `лек; сем` объединены в золотистый тег `ЛЕК · СЕМ`, экзамены/зачёты фиолетовые.
- Один мобильный интерфейс; на ПК центральная область расширяется до 720 px с пустыми боковыми полями.

## Реальная интеграция

Фиксированный адрес: `POST https://raspis.rggu.ru/api/Get_Schedule_Table`. httpx формирует multipart автоматически. Форма, курс и ID потока берутся из каталога. Для «ПИ ПИИ» это `eduform=3`, `course=2` и `flow=119_1`. Для всех запросов используются `intervalMode=4` и `menuMode=flow`. Cookies, токены, авторизация и ручные границы multipart не используются.

Проверка 02.11.2026: сервер вернул период **24.08.2026–21.03.2027**, 76 дней с занятиями и 224 записи. Backend дополнил период до 210 календарных дней. Это период, заявленный университетом; наличие всех будущих занятий университет может уточнять позднее. Приложение не трактует семестр по собственным датам и не добавляет выдуманные занятия.

Все `flows` сохраняются как отдельные карточки, включая исходные идентификаторы в `source`. Соседние пары не объединяются. Количество пар считается по уникальным номерам внутри дня. Отсутствующие в ответе даты внутри периода считаются свободными, вне периода показывается отсутствие данных. Произвольные прошлые/будущие семестры пока не запрашиваются: способ их выбора не подтверждён.

## API и кеш

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/health` | Состояние процесса и часовой пояс |
| GET | `/api/groups` | Зарегистрированные группы |
| GET | `/api/config` | Доступность ручного обновления |
| GET | `/api/schedule?group_id=119_1` | Нормализованный семестр |
| POST | `/api/schedule/refresh?group_id=119_1` | Ручное обновление для закрытых установок |

Backend загружает семестр по запросу выбранной группы и хранит его в кеше 15 минут. Смена дат в интерфейсе не обращается к университету. Параллельные обращения одной группы объединяются через lock. Интервал между попытками, включая неуспешные, — не менее 60 секунд; принудительные повторения получают HTTP 429 и `Retry-After`.

Ручное обновление по умолчанию отключено. POST на `/api/schedule/refresh` возвращает 403, а интерфейс скрывает кнопки обновления в календаре и настройках. Для закрытой установки можно задать `RGGU_ALLOW_MANUAL_REFRESH=true` в `backend/.env` и перезапустить сервер. Обычная загрузка обновляет данные по истечении кеша.

При сбое доступны последние корректные данные, пока их возраст не превышает 7 дней; они помечаются как устаревшие. `fetched_at` при этом не меняется. После перезапуска сервера кеш пуст. Используется один процесс Uvicorn: кеш и ограничение частоты хранятся в памяти, а не распределяются между несколькими worker-процессами.

`/api/health` сообщает о работоспособности нашего процесса; это не гарантия доступности университета. Недоступность университета возвращает HTTP 503 без traceback. Переданные ID проверяются по реестру, произвольные URL клиент передать не может.

## Конфигурация

Скопируйте `backend/.env.example` в `backend/.env` при необходимости. Основные параметры: TTL, интервал обновления, максимальный возраст устаревшего кеша, таймаут и список CORS origins. Сервер запускается из каталога `backend`, чтобы `.env` находился рядом.

Каталог хранится в `backend/app/config/group_catalog.json`. Чтобы обновить его, выполните из корня проекта `.\.venv\Scripts\python.exe backend/import_groups.py` и перезапустите backend. Импорт оставляет группы ИИНиТБ из публичных списков РГГУ и заменяет файл после завершения всех запросов. Ключ группы состоит из формы, курса и ID потока. Для существующей группы сохранён ключ `119_1`.

Звонки задаются в `backend/app/config/bells.py`.

Ключи localStorage: `rggu-schedule:selected-group`, `rggu-schedule:saved-groups`, `rggu-schedule:theme`, `rggu-schedule:accent`, `rggu-schedule:organize-past`, `rggu-schedule:nickname`. Сброс удаляет только настройки этого приложения и возвращает значения по умолчанию. Если браузер блокирует хранилище, текущий сеанс работает, но настройки не сохранятся.

## Публикация

`start.ps1` предназначен для локального запуска и проверки по Wi-Fi. Для публичной установки соберите фронтенд командой `pnpm run build` из каталога `frontend` и раздавайте `frontend/dist` по HTTPS. Прокси должен направлять `/api` на FastAPI по внутреннему адресу и ограничивать частоту публичных запросов. Оставьте `RGGU_ALLOW_MANUAL_REFRESH=false`.

## Офлайн-режим

Откройте готовую сборку с интернетом на том устройстве и в том приложении, где планируете пользоваться ей офлайн. После загрузки сервис-воркер сохраняет интерфейс, иконки и шрифты. Приложение сохраняет расписания добавленных групп, включая основную. При добавлении группа загружается в фоне, при удалении её копия убирается из кеша. Полный каталог остаётся доступен через сервер.

Без связи можно перезапустить приложение, открыть сохранённое расписание и переключаться между сохранёнными группами. Время получения данных видно в настройках. Поиск новых групп показывает «Ждём подключения» до восстановления связи. Если расписание конкретной группы ещё не успело загрузиться, для неё потребуется подключение.

На iPhone используйте HTTPS. Локальный адрес вида `http://192.168.x.x:5173` подходит для просмотра по Wi-Fi. Для проверки офлайн-режима на ПК соберите фронтенд, запустите backend и откройте `pnpm exec vite preview --host 127.0.0.1` из каталога `frontend`. После загрузки расписания остановите оба сервера и перезагрузите вкладку.

При размещении отдавайте `/service-worker.js` и `/index.html` с перепроверкой кеша при запросе. Старый офлайн-интерфейс заменяется новой сборкой после закрытия открытых экземпляров приложения.

Сервис независимый и не является официальным сайтом РГГУ. Оригинальное расписание доступно на сайте РГГУ.

## Шрифты и движение

Интерфейс использует локальные variable-шрифты [Onest](https://fontsource.org/fonts/onest) и [Manrope](https://fontsource.org/fonts/manrope): текст/управление и крупные заголовки соответственно. В production входят четыре файла WOFF2 (латиница и кириллица), всего около 89 КБ. Файлы лицензий SIL OFL поставляются в `frontend/public/fonts`.

Выделение нижнего бара перемещается за 300 мс. Проявление экранов, меню и диалогов занимает 140–260 мс; нажатия получают лёгкую обратную связь. При системной настройке уменьшения движения все CSS-анимации и переходы отключаются. Обновления часов не меняют ключи экранов и не запускают их появление заново.

В Настройках можно указать локальное имя или никнейм (до 64 символов, без эмодзи). Оно сохраняется автоматически, заменяет «Студент» в приветствии и задаёт первый символ аватара. Длинное имя обрезается в одну строку с многоточием. Пустое поле возвращает стандартное обращение; общий сброс локальных данных очищает имя.

## Первый вход MyRSUH

При первом запуске доступны три шага: знакомство с нашим расписанием, поиск группы в каталоге РГГУ, затем необязательное имя, тема и акцент. Группа сохраняется по кнопке «Готово». Уведомления, роли и регистрация не добавляются. При последующих открытиях приложение сразу переходит на Главную.

Для повторного прохождения можно воспользоваться существующей кнопкой «Сбросить локальные данные» в Настройках: она удалит локальное имя, выбранные группы и оформление в этом браузере.
